# 数据来源、标注与划分说明

> 课程要求：准备不少于 **80 个独立图像或视频片段**，包含正常、危险和容易混淆的场景；
> 建立人工标注；划分开发集与固定测试集；**同一视频的相邻帧不得分散到两个集合中**；
> **测试集不得用于策略更新或案例记忆**。

---

## 一、数据来源

### 允许的来源

| 来源 | 说明 | 注意事项 |
| --- | --- | --- |
| 自行拍摄的正常实验室场景 | 首选。可控、可授权、可复核 | 拍摄前须取得实验室负责人与在场人员同意 |
| 学校公开的实验教学 / 宣传视频 | 画质好、场景真实 | 仅使用公开发布且允许教学使用的素材 |
| 网络公开图片 | 补充类别不均衡 | 必须确认授权许可；不得用于商业用途 |
| 数据集样例图 | 补充易混淆样本 | 记录来源与许可 |

### 严禁的做法

- **不得制造危险情境采集数据**（不得为了拍“热源旁放溶剂”而真的把溶剂放到加热板上）。
- **不得拍摄真实事故现场**。
- 不得使用包含他人隐私（工牌、姓名、面部特写）且未获得同意的素材。
- 不得使用来源不明、无法确认授权的图片。

### 本仓库中的占位数据

`data/demo/` 由 `scripts/make_demo_dataset.py` 程序化生成，是**纯色块 + 文字标注的占位图**，
仅用于验证流程能否跑通，**不是实验数据**。正式提交前请执行：

```bash
python scripts/reset_demo_state.py --yes
```

然后换成自行采集的真实数据。

## 二、数据规模建议

| 类别 | 数量 | 说明 |
| --- | --- | --- |
| 正常场景 | ≥ 30 | 用于检验系统会不会乱报警（对应“误报率”） |
| 明确风险场景 | ≥ 40 | 5 类风险各 ≥ 8 个 |
| 容易混淆场景 | ≥ 10 | 必须单独统计，这是评测“证据复核 Agent 是否有效”的关键 |

总计 **≥ 80 个独立样本**。拍摄视频时，一个视频片段算一个样本（不是一帧算一个）。

### 五类风险

| risk_type | 中文 | 典型样本 |
| --- | --- | --- |
| `ppe_missing` | 个人防护装备缺失 | 未穿实验服 / 未戴护目镜 / 未戴手套进行液体操作 |
| `reagent_management` | 试剂管理异常 | 试剂瓶敞口、标签缺失或被遮挡、性质相抵触试剂混放 |
| `flammable_near_heat` | 热源附近易燃物 | 酒精灯 / 加热板旁有纸张、手套、有机溶剂 |
| `food_or_drink` | 实验区饮食 | 实验台上有水杯、饮料、食物 |
| `spill_or_obstruction` | 洒漏或通道阻塞 | 地面液体、电线横穿通道、安全出口被堵 |

### 容易混淆样本要覆盖的典型情形

这些是当前系统最容易出错的场景，务必专门采集：

1. 透明水杯 / 洗瓶 / 纯水试剂瓶 → 容易被误判为 PPE 缺失或饮食风险；
2. 拍摄角度或头发遮挡 → 护目镜被遮住，容易被误判为未佩戴；
3. 已断电冷却的加热设备 → 容易被误判为工作中的热源；
4. 地面反光、阴影、深色地垫 → 容易被误判为液体洒漏；
5. 靠墙摆放、未阻塞通道的纸箱 → 容易被误判为通道阻塞；
6. 标签被手或器皿遮挡的试剂瓶 → 容易被误判为标签缺失。

### 采集后怎么导入

三个人各自用手机拍，文件名一定重复（都是 `IMG_0001.jpg`），还会有重复提交、
GPS 定位、竖拍旋转、视频帧跨集合这些问题。**不要手工拷贝和改名**，用脚本：

```bash
# 1) 把所有人的照片/视频原样扔进 data/inbox/（可以有子文件夹，不用管文件名）
# 2) 一条命令整理
python scripts/ingest_photos.py
```

它会依次完成：

| 步骤 | 解决什么 | 为什么必须做 |
| --- | --- | --- |
| MD5 去重 | 同一张照片被两人提交 | 重复样本会同时进 dev 和 test，指标虚高 |
| 剥除 EXIF | 手机照片带 GPS 坐标 | 直接把学校位置传到 GitHub 上，是隐私事故 |
| 纠正旋转 + 缩放到 1600px | 竖拍照片方向错、文件过大 | 方向错会严重影响模型判断 |
| 统一编号 `lab_0001` | 文件名冲突互相覆盖 | 评测靠 `sample_id` 对齐 |
| **以视频为单位**划分 dev/test | 相邻帧被分到两个集合 | 测试集里出现训练见过的画面，课程明令禁止 |
| 产出 `data/labels_draft.csv` | 标注从空白开始 | `risk_type` 故意留空，**标注必须人工做** |

> `scripts/ingest_photos.py` 只会在 `notes` 里写「文件名提示可能是某类风险」，
> **绝不会自动填 `risk_type`**。脚本猜出来的标注会让整个实验失去意义。

划分种子固定（`--seed`，默认 20261016），换台电脑重跑得到同样结果，
这样三组对比实验才可复现。

## 三、标注格式

采用 CSV，一行代表「样本 × 风险」的一个对应关系。
**一个样本有多种风险就写多行；正常样本写一行 `risk_type=normal`。**

文件：`data/labels_dev.csv`、`data/labels_test.csv`

| 字段 | 说明 |
| --- | --- |
| `sample_id` | 样本编号，需与文件名（去扩展名）一致，评测时靠它对齐 |
| `file_path` | 相对项目根目录的路径，如 `data/dev/lab_0001.jpg` |
| `split` | `dev` 或 `test` |
| `risk_type` | 五类风险之一；正常样本填 `normal` |
| `severity` | `low` / `medium` / `high` / `uncertain` / `normal` |
| `evidence` | 人工标注的可见证据（写清看到了什么、在哪） |
| `location` | 风险位置 |
| `notes` | 备注；易混淆样本请标注“容易混淆”及原因 |

示例：

```csv
sample_id,file_path,split,risk_type,severity,evidence,location,notes
lab_0001,data/dev/lab_0001.jpg,dev,normal,normal,台面整洁，人员防护齐全,无,正常样本
lab_0002,data/dev/lab_0002.jpg,dev,ppe_missing,medium,人员正操作烧杯但面部未见护目镜,画面中央,风险样本
lab_0003,data/dev/lab_0003.jpg,dev,food_or_drink,low,实验台右缘有透明水杯,右侧边缘,容易混淆：易与器皿混淆
```

模板见 `data/labels_template.csv`。

## 四、划分规则

| 集合 | 占比 | 用途 | 硬性约束 |
| --- | --- | --- | --- |
| 开发集 `dev` | 60% | 调试提示词、规则、案例记忆，以及**自进化** | 可以反复使用 |
| 固定测试集 `test` | 40% | **只在最终评测时使用** | 不得参与任何策略更新或案例记忆 |

必须遵守：

1. **同一段视频的相邻帧不能分散到两个集合。** 本系统对视频是按时间轴抽帧的，
   如果同一视频的帧同时出现在 dev 和 test，会导致评测虚高。
   建议以「视频片段」为单位整体划分。
2. **测试集绝不用于自进化。** `scripts/run_experiment.py` 已强制这一点：
   自进化只读 `--dev-labels`，评测只读 `--labels`。
3. 划分完成后不要为了「调好看」而重新洗牌。如果必须调整，请在报告中说明并重跑全部实验。

## 五、评测口径

`src/evaluate.py` 采用**多标签**口径：

- 系统输出 `confirmed` / `simulated` / `analyzed` 的风险类型，计为“报了该风险”；
- 输出 `uncertain` 计为**弃权**（单独统计弃权率，用于回答“证据不足时能否正确说不确定”）；
- 输出 `rejected` 计为未报该风险。

指标：per-class 与 macro/micro 的 Precision / Recall / F1、误报样本率、漏报样本率、弃权率，
以及处理时间与模型调用次数（成本）。
