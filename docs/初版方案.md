# 工科导论合作课题初版方案

> **v0.2 修订说明（2026-10-16）**
>
> 本文档是**最初的设计方案**，保留作为演进记录。当前代码实现已在它基础上做了实质性升级：
>
> | 方面 | 初版方案 | 当前实现（v0.2） |
> | --- | --- | --- |
> | Agent 推理 | 只有感知 Agent 用模型 | 三个 Agent 全部接入模型推理，各带确定性回退 |
> | 工具调用 | 流水线写死顺序 | **Agent 自主申请工具**，结果回灌，最多 2 轮 |
> | 意见不一致 | 仅单向降级 | **冲突检测 + 保守优先仲裁 + 人工优先复核队列**，报告单列冲突表 |
> | 视频分析 | 逐帧独立后按类型去重 | **跨帧时间融合**：持续帧数、出现比例、瞬时误检降级 |
> | 自进化 | 追加固定话术 | **策略进化 Agent 提案**（易混淆说明 / 提示词补丁 / 新增规则）+ 版本递增防撞车 |
> | 评测 | 单标签、无总体指标 | 多标签 + macro/micro P/R/F1 + 误报漏报率 + 弃权率 + **处理时间与调用成本** |
> | 对照组 | 未实现 | **基础识别系统（单模型直出）** + 一键三组对比脚本 |
> | 可信度 | 模拟结果会被标为已确认 | 新增 `simulated` 状态，模拟结果永不冒充真实结论 |
>
> 详细的运行方式见 `README.md`，实验与报告写法见 `docs/项目报告大纲.md`。

## 1. 项目题目

**基于多模态大模型与自进化智能体的实验室危险场景识别与预警系统**

第一版建议先聚焦 **高校化学/材料实验室**，不做工业现场和数字孪生。理由：

- 数据更容易合法、安全地获取，不需要制造危险情境。
- 风险类型清晰，适合用图像/短视频验证。
- 容易做出完整闭环：识别 → 多 Agent 协作 → 工具调用 → 人工反馈 → 策略更新 → 效果验证。

---

## 2. 第一版目标

做一个可演示、可评测、可迭代的 **v0.1 原型系统**：

1. 支持上传实验室图片或短视频。
2. 识别至少 4 类风险：
   - PPE 缺失：未穿实验服、未戴护目镜、未戴手套。
   - 试剂管理异常：试剂瓶敞口、标签缺失、混放。
   - 热源附近存在易燃物：酒精灯/加热板附近有纸张、溶剂、手套等。
   - 实验台违规饮食或水杯放置。
   - 可选扩展：地面液体、通道堵塞、电线绊倒风险。
3. 输出风险类别、位置/时间段、风险等级、可见证据、处理建议、不确定性。
4. 至少 3 个 Agent 协作：
   - 场景感知 Agent：描述画面、提取候选风险。
   - 风险分析 Agent：结合安全规则判断风险等级和建议。
   - 证据复核 Agent：检查证据是否充分，降低误报。
5. 支持工具调用：
   - 视频抽帧。
   - 局部裁剪。
   - 安全规则检索。
   - 历史案例记忆检索。
   - 工具调用日志保存。
6. 支持人工反馈后的自进化：
   - 保存纠错案例。
   - 生成规则/提示词修改建议。
   - 保存策略版本，支持回退。
7. 支持导出安全分析报告。
8. 建立 80 个以上样本的数据集和固定测试集。

## 3. 推荐技术路线

### 3.1 总体架构

```text
图片/短视频输入
    ↓
输入预处理与视频抽帧
    ↓
场景感知 Agent
    ↓
自主工具调用：目标检测 / 裁剪 / 规则检索 / 案例检索
    ↓
风险分析 Agent
    ↓
证据复核 Agent
    ↓
风险报告与界面展示
    ↓
人工纠错
    ↓
自进化模块：更新提示词、规则或案例记忆
    ↓
版本保存与效果复测
```

### 3.2 模型与工具

第一版不追求从零训练模型，建议使用现成能力：

- 多模态大模型：任意 OpenAI 兼容视觉模型 API。
- 目标检测：可接入 YOLOv8/YOLO11 或先用大模型输出候选区域。
- 视频处理：OpenCV 抽帧。
- 前端：第一版用本地 HTML 演示界面，后续可升级 Streamlit/Vue。
- 后端：Python 模块化 pipeline。
- 数据存储：JSON/JSONL 文件即可，便于课程展示和版本管理。

### 3.3 Agent 分工

#### Agent A：场景感知

输入：

- 图片路径或视频抽帧结果。
- 场景说明：高校实验室。
- 当前策略版本中的感知提示词。

输出：

- 场景描述。
- 候选风险列表。
- 每个候选风险的可见证据。
- 置信度和不确定性。

#### Agent B：风险分析

输入：

- Agent A 的候选风险。
- 检索到的安全规则。
- 历史纠错案例。

输出：

- 风险类型。
- 风险等级：低/中/高。
- 处理建议。
- 需要补充的证据或工具调用。

#### Agent C：证据复核

输入：

- Agent B 的结构化结果。
- 原始图像或裁剪区域。
- 工具调用记录。

输出：

- 复核后风险列表。
- 被降级的风险。
- 被拒绝的误报。
- 与风险分析 Agent 的冲突说明。

## 4. 风险等级初版定义

| 等级  | 定义           | 示例                       |
| --- | ------------ | ------------------------ |
| 高   | 可能立即导致伤害或事故  | 加热设备旁有易燃溶剂；强酸试剂敞口且靠近人员手部 |
| 中   | 明显违规，可能发展为事故 | 未戴护目镜进行液体操作；试剂瓶标签缺失      |
| 低   | 不规范但短期风险较低   | 水杯放在实验台边缘；实验服未完全穿好       |
| 不确定 | 证据不足，不能可靠判断  | 手部被遮挡，无法确认是否戴手套          |

## 5. 数据方案

### 5.1 数据来源

建议优先使用：

- 自己拍摄的正常实验室场景。
- 学校公开宣传视频/实验教学视频中的安全场景。
- 网络公开图片，注意授权和隐私。
- 不制造危险动作，不拍摄真实事故。

### 5.2 数据规模

第一版最低要求：

- 80 个独立图像或短视频片段。
- 正常样本约 30 个。
- 明确风险样本约 40 个。
- 容易混淆样本约 10 个。

### 5.3 数据划分

- 开发集：60%，用于调试提示词和规则。
- 固定测试集：40%，只用于最终评测，不参与自进化。
- 同一视频的相邻帧不能同时进入开发集和测试集。

### 5.4 标注格式

每个样本记录：

```json
{
  "sample_id": "lab_0001",
  "file": "data/dev/lab_0001.jpg",
  "scene": "chemistry_lab",
  "labels": [
    {
      "risk_type": "ppe_missing",
      "severity": "medium",
      "evidence": "人员正在操作烧杯，但面部未见护目镜",
      "location": "画面中央偏左"
    }
  ]
}
```

## 6. 自进化设计

第一版不要做成“模型自己随便改”。建议采用 **人工确认式自进化**：

1. 用户发现误报/漏报。
2. 系统记录原输入、原输出、人工修正、修正原因。
3. 自进化模块生成修改建议：
   - 增加/修改规则。
   - 修改感知提示词。
   - 添加案例记忆。
4. 组员确认后生成新版本策略。
5. 系统在开发集上复测。
6. 如果效果变差，可回退到旧版本。

建议完成两轮：

- v0.1：基础规则 + 基础提示词。
- v0.2：根据第一轮误报/漏报修正。
- v0.3：加入案例记忆和冲突处理优化。

## 7. 评测方案

至少比较三组：

1. 基础识别系统：单模型直接输出结果。
2. 多 Agent + 工具调用系统。
3. 两轮自进化后的系统。

指标：

- 精确率 Precision。
- 召回率 Recall。
- 误报数。
- 漏报数。
- 平均处理时间。
- 模型调用次数/成本。
- 证据不足时是否能正确输出“不确定”。

消融实验：

- 关闭证据复核 Agent。
- 关闭规则检索。
- 关闭案例记忆。

## 8. 展示与报告结构

最终项目报告建议按下面写：

1. 项目背景与需求。
2. 场景选择与风险定义。
3. 系统架构。
4. Agent 协作机制。
5. 工具调用与自主决策。
6. 自进化策略。
7. 数据来源、标注与划分。
8. 实验结果与对比。
9. 失败案例分析。
10. 局限性与后续计划。

课堂演示建议：

- 先用 1 张正常图说明系统不会乱报警。
- 再用 2 张风险图说明识别、证据和建议。
- 展示一次人工纠错和版本更新。
- 最后展示评测表。
