# 实验结果与分析

> 数字来自 2026-10-23 的一次完整运行，经 2026-10-25 修正后重算（见第二节开头说明）。  
> **本文件不美化结果**：两轮自进化后指标下降，照实写；`ppe_missing` 在多 Agent 组召回为 0，也照实写。

## 二、三组对比

> ⚠️ **本节的数字是 2026-10-25 修正后重算的**。此前版本（F1 = 0.479 / 0.535 / 0.438）
> 作废，原因是评测时标注与报告的 `sample_id` 命名不一致，**18/43 个样本的预测根本没进指标**
> （详见 `docs/失败案例记录.md` 案例 E10）。同时修正了 3 处人工错标（见同一文档 E11）。
> 模型输出没有变，变的是评测口径 —— 重算命令见 `scripts/recompute_metrics.py`。

| 实验组 | Macro P | Macro R | Macro F1 | Micro F1 | 误报样本率 | 漏报样本率 | 弃权率 | 分析失败 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 基础识别系统（单模型直出） | 0.192 | **0.813** | 0.307 | 0.298 | 0.791 | **0.093** | 0.000 | 0 |
| 多 Agent + 工具调用 | **0.470** | 0.550 | **0.500** | **0.545** | **0.140** | 0.209 | 0.046 | 0 |
| 两轮自进化后（v0.4） | 0.365 | 0.557 | 0.397 | 0.400 | 0.419 | 0.209 | 0.046 | 0 |

修正前后差别最大的地方在**基础系统的误报率**：37.2% → **79.1%**。
原因是基础系统对多数画面会一次性报出多类风险（"看到有人有瓶子就报警"），
这些误报此前因为 ID 不匹配全被丢掉了。

### 发现 1：多 Agent 用「漏报换误报」，方向是对的

- 误报样本率从 **79.1% 降到 14.0%**（降幅 82%）；
- 精确率从 0.192 升到 **0.470**，Macro F1 从 0.307 升到 **0.500**；
- 代价是召回从 0.813 掉到 0.550，漏报率从 9.3% 升到 20.9%。

这不是"变强了"，而是**判断口径变了**：基础系统看到实验室里有人有瓶子就报警，  
复核 Agent 要求"看得见的证据"，够不上就判 `uncertain` 或驳回。  
在实验室场景里，这个方向比高召回更合理 —— 天天误报的系统没人会看。

代价必须说清楚：**漏报率接近翻倍**。如果一个漏报的代价远高于一次误报，  
这个取舍就不该这么选，此时应当调低复核阈值而不是照抄本配置。

### 发现 2：两轮自进化后指标反而下降 —— 负面结果，但原因可查

F1 从 0.500 掉到 0.397，误报率从 14.0% 反弹到 **41.9%**。逐版本追查：

| 版本   | 提案来源                                     | 改了什么                  | 后果                                                                                  |
| ---- | ---------------------------------------- | --------------------- | ----------------------------------------------------------------------------------- |
| v0.3 | `llm_agent`（模型自己提案）                      | 新增 3 条「易混淆说明」+ 2 条新规则 | 其中一条写成「检测到人员未佩戴 PPE 时应**立即报警**」——这是**处置建议**，不是易混淆说明，塞进感知提示词等于命令模型更激进地报警             |
| v0.4 | `rule_based_fallback`（**模型提案失败，回退规则驱动**） | 一次性新增 7 条「X↔normal」约束 | 每条都写着「证据不足时应输出 uncertain 而不是硬报风险」，叠加后系统过度保守，`spill_or_obstruction` 召回从 0.75 掉到 0.25 |

三个直接教训：

1. **自进化的载体用错了位置**。把处置建议（"应立即报警"）写进"易混淆说明"，  
   效果与意图相反。载体分类需要校验。
2. **第二轮模型提案失败**，系统回退到规则驱动的兜底方案。兜底方案能用，  
   但它一次性堆了 7 条约束，没有评估"少量多次"的必要性 —— 提示词被一口气改太多，  
   无法归因到底是哪条起了负面作用。
3. **"进化"不等于"变好"**。没有测试集（本次只用 dev 集自进化）时，  
   系统会朝"在 dev 上少报错"的方向过拟合，泛化到 test 反而更差。

> 这一点对答辩很重要：如果只说"我们实现了自进化且效果提升"，审阅者一问  
> "提升多少、怎么保证不退化"就露馅了。如实报告负结果 + 归因，比虚假提升有价值。

### 发现 3：`ppe_missing` 在多 Agent 组召回为 0，另两组各抓到一点

| 组 | 支持数 | TP | FP | FN | Precision | Recall |
| --- | --- | --- | --- | --- | --- | --- |
| 基础系统 | 5 | 2 | 11 | 3 | 0.154 | 0.400 |
| 多 Agent | 5 | 0 | 0 | 5 | 0.000 | **0.000** |
| 两轮自进化 | 5 | 1 | 1 | 4 | 0.500 | 0.200 |

> 注：修正标注后 `ppe_missing` 测试样本从 4 个变成 5 个
> （`8851786` 原标 normal，复核发现两人均未戴护目镜，改为 `ppe_missing`）。
> 此前"全组召回都是 0"的说法不成立 —— 基础系统靠"地毯式报警"蒙对 2 个，
> 两轮自进化组抓到 1 个（正是 `8851786`）。**但多 Agent 组确实是 0**，
> 而且这个 0 更有意义：它说明复核 Agent 在压制误报的同时，
> 把这类"画面里没有的东西"也一起压掉了。

5 个测试样本中 4 个合成样本的实际判定：

| 样本                     | 真实标注       | 系统输出                                 |
| ---------------------- | ---------- | ------------------------------------ |
| `synth_ppe_missing_02` | 两名学生未戴护目镜  | `flammable_near_heat`（把画面里的电热板当成风险源） |
| `synth_ppe_missing_03` | 徒手操作无护目镜   | `reagent_management`（只注意到台面上的瓶子）     |
| `synth_ppe_missing_05` | 通风橱前短袖无护目镜 | `food_or_drink`                      |
| `synth_ppe_missing_06` | 两人讨论均未戴护目镜 | `food_or_drink`                      |

**根因：这是「缺失型风险」，与「存在型风险」是两类不同难度的问题。**

- `spill_or_obstruction`、`food_or_drink` 是**存在型**：画面里有个显眼物体，模型看到就能报。
- `ppe_missing` 是**缺失型**：要判断"应该戴护目镜但没戴"，模型必须  
  ① 锁定人脸 → ② 判断眼部有没有透明护目镜 → ③ 结合"正在进行液体操作"推断应该戴。  
  全景图里人脸只有几十像素，透明护目镜又几乎不留视觉特征，模型直接跳过这一步，  
  转而去报告画面里最显眼的物体。

这个失败模式对改法有直接指导意义：`ppe_missing` 不能靠"再强调一遍要检查护目镜"，  
必须**先用 `crop_region` 把人脸裁出来放大再判断** —— 这正是 Agent 自主工具调用  
本该发挥作用的地方，但当前模型并没有主动申请这个工具。这是下一版最明确的改进点。

## 三、消融实验（关闭关键功能）

策略固定为 v0.2，测试集不变，只关掉一个功能：

| 配置 | Macro F1 | 误报样本率 | 漏报样本率 |
| --- | --- | --- | --- |
| 完整系统（参照） | **0.500** | **0.140** | 0.209 |
| 关闭证据复核 Agent | 0.442 | **0.302** | 0.186 |
| 关闭 Agent 自主工具调用 | **0.500** | 0.163 | 0.209 |

### 证据复核 Agent 是抑制误报的主力

- 关掉后误报率 **14.0% → 30.2%（翻 2.16 倍）**，F1 掉 0.058；
- 漏报率同时从 0.209 降到 0.186 —— 说明这个 Agent 的作用就是**把可疑结论拦下来**，
  它拦对了一些（减少误报），也拦错了一些（增加漏报）。

### 关掉自主工具调用，指标几乎不动 —— 一个诚实的负面结果

两组的 Macro F1 完全一样（0.500 vs 0.500），误报率只差 2.3 个百分点
（14.0% vs 16.3%），漏报率一模一样（0.209）。

**也就是说：在这份测试集上，「Agent 自主选择并调用工具」没有带来可测量的精度提升。**

这不代表工具调用没用，而是说明当前实现里它更多体现在**过程可解释性**上
（报告里能看到 Agent 申请了 `crop_region`、查了哪条规则），而不是结果改善。
原因大概有两个：

1. 触发条件太窄。模型很少主动申请裁剪，`ppe_missing` 这类最需要放大的场景
   反而一次都没触发（见上一节的失败分析）。
2. 工具返回的信息没有真正改变结论。例如查到规则后，模型多半只是把规则原话
   写进证据，并不因此改判。

写进报告时不必回避这一点：**课程要求的"自主工具调用"我们实现了、日志有记录、
能演示，但它在总体指标上暂时无效**，这正是下一版要改的地方。

**但有一个反向证据不能省：** 看下一节的易混淆样本统计，关掉工具后误报从 **1/8 涨到 3/8**。
说明工具（规则检索、案例检索）对"识破陷阱"是有效的，只是这 2 个样本的改善
被其他 35 个样本的波动盖住了，在 Macro F1 上看不出来。

所以准确的说法是：**工具调用的价值集中在少数难样本上，不在整体均值上。**
这也提醒一件事——只看 Macro F1 会漏掉这类局部作用，分类别和分子集看才有意义。

### 易混淆样本的表现更直观

测试集里有 8 张精心构造的"看起来像违规、实际合规"样本，各组误报数：

| 组          | 误报        | 说明               |
| ---------- | --------- | ---------------- |
| 基础系统       | **8 / 8** | 一张不落地全报了         |
| 多 Agent    | **1 / 8** | 只剩一张没识破          |
| 两轮自进化后     | 4 / 8     | 进化把已经修好的又改回去了    |
| 关闭复核 Agent | 3 / 8     | 复核是识破陷阱的关键       |
| 关闭工具调用     | 3 / 8     | 检索规则/案例对识破陷阱也有贡献 |

这组数字比 Macro F1 更能说明问题：**基础系统在"陷阱样本"上完全失效**，  
它的高召回是靠"什么都报"换来的。

## 四、成本对比

| 实验组     | 平均耗时     | 平均模型调用 | 平均工具调用 | 43 样本总调用 |
| ------- | -------- | ------ | ------ | -------- |
| 基础系统    | 4865 ms  | 1.00   | 0.0    | 43       |
| 多 Agent | 6971 ms  | 1.98   | 1.0    | 85       |
| 两轮自进化后  | 11652 ms | 2.63   | 1.0    | 113      |

- 多 Agent 的成本约为基础的 **2 倍调用 / 1.4 倍时间**，换来误报率降 75%，这个交换比可以接受；
- 自进化后成本涨到 **2.6 倍调用 / 2.4 倍时间**，指标还变差了 —— 提示词膨胀（7 条易混淆说明  
  被反复注入）既拖慢速度又没带来收益，是应该被回退的版本。

## 五、结论

1. **多 Agent + 证据复核切实有效**，但主要收益在"减少误报"，而不是"提高召回"。
2. **自进化机制跑通了，但这一轮的进化方向是错的**。系统能提出方案、能晋升、能回退，  
   机制可用；问题在于提案质量与叠加策略，这恰恰是人（组员确认环节）应该拦下来的地方。
3. **缺失型风险（`ppe_missing`）是当前系统的硬伤**，需要靠工具调用（人脸裁剪）解决，  
   而不是靠提示词。
4. 数据集一半是合成图，**结论的外部效度有限**，换成实拍必须重跑。
